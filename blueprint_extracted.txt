1. Executive Summary
ChaseHorse is a pan-India employee management and field-task execution platform. Customers and authorized administrators create field-work tasks. Eligible employees discover nearby tasks, accept or reject them, travel to the task location, complete the required work and submit photographic evidence. AI assists with evidence verification, while an Operations Manager reviews exceptions and approves completion. Once the required approval conditions are met, the task reward is credited to the employee’s in-app wallet ledger.
The initial release will focus on reliable task workflows, location-aware discovery, evidence capture, approval controls and a trustworthy wallet ledger. Task fields and checklist templates will remain configurable until the business rules are finalized.
2. Goals and Scope
Primary goals
Manage employees, customers, administrators and Operations Managers through a role-based platform.
Support field tasks across India and show eligible tasks near an employee’s current location.
Require a task-specific checklist so employees can confirm that every required activity is completed.
Capture task evidence through the app, preserving original files and recording relevant metadata.
Use AI to assist with evidence checks without treating AI output as unquestionable proof.

4. End-to-End Task Workflow
Task creation: 
An authorized customer or administrator creates a task with its required fields, location, reward and checklist/template.
Eligibility and discovery: 
The backend returns open tasks that match the employee’s eligibility and configured geographic radius.
Accept or reject: 
The employee accepts or rejects the task. Acceptance is atomic so the same exclusive task cannot be assigned twice.
Travel and execution: 
The employee navigates to the task location and completes the work and checklist items.
Evidence capture: 
The employee captures required photos in the app and submits them with task context and metadata.
Automated checks: 
The system checks required evidence, metadata, location consistency and likely duplicate content; AI returns a result, confidence and reasons.
Manager review: 
The Operations Manager reviews evidence and AI flags, then approves, rejects or requests rework with a reason.
Reward credit: 
After all configured approval conditions pass, the backend records one reward credit in the employee’s wallet ledger.
Closure and audit: 
The task is closed and its status history, decisions, evidence references and ledger reference remain auditable.
5. Task Checklist Requirements
Each task should support a checklist of required activities. The checklist may be selected from a reusable template or defined for a specific task. Employees should be able to see progress (for example, 3 of 5 complete), and required items must be completed before final submission unless an authorized exception is recorded.
Checklist capability
Requirement
Checklist template
Reusable checklist templates for common task types; version templates so changes do not silently alter active tasks.
Checklist items
Each item has a label/instruction, required/optional flag, order, and optionally an evidence requirement.
Completion state
Track incomplete, complete and not-applicable states; require a reason and permission for not-applicable items.
Evidence per item
Optionally require a photo or note for a specific checklist item.
Submission validation
Backend verifies all required checklist items before allowing task submission.
Review
Manager can see checklist results and evidence together; rejected items include a reason for rework.
Audit history
Record who changed an item and when; preserve the submitted checklist snapshot.

7. Evidence, Location and AI Verification
Use the in-app camera for required task evidence and upload files to private object storage.
Preserve the original image; create a separate stamped presentation copy if the UI needs a visible timestamp, location and task reference.
Store server upload time, uploader, task ID, storage path, file hash and available capture/GPS metadata.
Compare reported coordinates with the task coordinates and allowed radius; consider GPS accuracy and flag suspicious or missing location data.
Detect likely duplicate images and check that the image appears relevant to the task and required checklist item.
AI output should include a result, confidence, reason codes and model/version metadata.
Low-confidence, mismatched or high-value submissions must go to manual review.
Do not rely on an image overlay alone as proof of authenticity; timestamps, EXIF data and GPS can be manipulated.
Define evidence retention, access and deletion rules, and obtain appropriate user consent for location/camera access.
8. Wallet and Reward Controls
Use an immutable wallet ledger with credit, debit, reversal and adjustment entries.
Create a task reward credit only after the required task and manager approval conditions pass.
Use a database transaction and idempotency key to prevent duplicate credits when requests are retried.
Link every wallet entry to the originating task and approval record.
Keep task reward approval separate from any later withdrawal or payout process.
Reconcile ledger entries and payout records; require additional permissions for manual adjustments.
Never trust reward amounts submitted by the mobile app; calculate and validate them on the server.

12. Security and Privacy Model
Apply role-based and record-level authorization on every protected API; do not rely on hiding buttons in the UI.
Ensure employees and customers can only access records they are permitted to see.
Keep database service-role credentials and AI/provider secrets on the server, never in mobile/web client bundles.
Use HTTPS, secure token storage, short-lived access tokens, refresh-token rotation, rate limiting and OTP attempt limits.
Use private evidence storage with short-lived signed URLs and access checks.
Record administrative changes, task decisions, approval outcomes and wallet events in audit logs.
Validate all task state transitions and checklist requirements on the backend.
Limit location collection to relevant workflows and define retention/access policies.
Test cross-user and cross-company access, replay/retry behavior, token expiry, file access and concurrent task acceptance.
13. UI/UX Direction
The product should feel like a premium field-operations platform rather than a generic ERP template: clean layouts, a clear information hierarchy, deep navy typography, restrained blue accents, generous spacing, readable status chips, rounded cards and subtle animations. Prioritize fast one-handed use for field employees.

Conclusion
ChaseHorse should be implemented around a controlled, auditable field-task lifecycle. The checklist is a core part of that lifecycle—not a cosmetic UI element—and must be enforced by the backend. AI can accelerate evidence review, but manager controls, location checks, secure evidence storage and an idempotent wallet ledger are essential for trustworthy reward processing. The next step is to confirm the task fields and checklist rules, then turn this blueprint into database migrations, API contracts and working screens.
